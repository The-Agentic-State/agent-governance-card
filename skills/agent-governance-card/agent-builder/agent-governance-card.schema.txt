# The card is a voluntary instrument: it records, computes, and recommends —
# it never blocks. Its to_resolve recommendations acquire binding force only
# where an adopting authority (e.g. a state CIO or agency directive) makes a
# completed card a precondition for production access. Say so when presenting
# verdicts; never present a recommendation as a prohibition.
adoption: >
  Voluntary instrument. to_resolve items are strong recommendations; they become
  gates only where an adopting directive makes the completed card a precondition
  for production access.

# R6: the answer-status vocabulary is part of the card, not just the instrument.
answer_statuses: [answered, unknown, not_applicable, not_in_place]
# unknown = the fact exists but can't be determined; not_in_place = the mechanism
# does not exist (a governance finding). Both are legal everywhere — but an unknown
# on an operational-tier derivation input floors the tier at Moderate (see below).

# R5: scope trigger + unit of analysis (front matter; not fields).
scope_trigger:
  card_required_if: >
    (interacts directly with the public) OR (materially influences a decision-making
    process with effect on the public or state resources), AND takes actions or
    produces outputs beyond returning static search results.
  out_of_scope: >
    embedded commodity features (autocomplete, spell-check, in-app summarization) and
    purely predictive back-office models — record in AI inventory; use an
    impact-assessment instrument for consequential predictive models.
  out_of_scope_boundary_test: >
    for the embedded-commodity carve-out, apply M-25-22 §2(b)'s two-part test: exempt
    only if (1) the product is widely available to the public for commercial use, AND
    (2) the AI is embedded in a product with substantial non-AI purposes. A product
    used primarily FOR its AI functionality (e.g. a licensed copilot) is in scope.
  scope_vs_high_impact_note: >
    intentional asymmetry with 2.5: the scope trigger ("materially influences a
    decision-making process") casts wider than 2.5's "principal basis" test. Scope
    decides whether a card exists at all; 2.5 is the legal test that decides the
    level. Many agents get a card and honestly answer 2.5 not_high_impact.
unit_of_analysis:
  one_card: one agent deployment in one operational context.
  platform_pattern: >
    parent card (shared layer: model, hosting and platform, vendor, identity
    architecture, exit terms) + one deployment addendum per context (purpose,
    data touched, autonomy, function).
